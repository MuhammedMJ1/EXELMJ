<task>
Make the Motion panel in EXELMJ Studio's design page fully operable from the keyboard,
in src/studio/motionPanel.ts, without changing the interaction model or the CSS compiler.

<context>
EXELMJ 0.4.0 is an Electron + TypeScript desktop app. Its design page has a Studio
with a Motion tab where a user records interactions — "make a button, press it, it
moves" — and the app compiles them to plain CSS that runs anywhere it is pasted.

The compiler already takes accessibility seriously: it emits a
@media (prefers-reduced-motion: reduce) block, and for a toggle it deliberately
ships four lines of script so the control is keyboard-reachable and reads correctly
to a screen reader. PROJECT_MAP records that as "the toggle's honest cost".

The authoring panel itself never got the same treatment. PROJECT_MAP's own entry for
it reads "M4 — motionPanel.ts: four decisions, no keyboard", and the file confirms it:
no keydown listener, no tabindex management, no role, no aria attribute anywhere in
568 lines. So the product ships accessible output from a panel that cannot be operated
without a mouse. Closing that gap is the point of this task.

The owner uses this panel daily and is not a programmer; the practical win is being
able to nudge a duration or a delay with arrow keys instead of dragging a 12px slider.
</context>

<requirements>
1. Every interactive control in the panel is reachable with Tab in visual order:
   preset buttons, add-motion, each motion card's name/play/delete, and inside an open
   card every select, range, number, colour and checkbox.
2. The preset strip does NOT create one tab stop per preset. It uses a roving
   tabindex: the strip is one tab stop, ArrowLeft/ArrowRight/Home/End move between
   presets, Enter or Space applies the focused one. There are 18 presets, so without
   this the strip alone costs 18 tab stops before anything else is reachable.
3. Arrow-key semantics are correct under an RTL (Arabic) UI: for the preset strip,
   ArrowRight moves toward the visually next item when the panel's computed direction
   is rtl, and toward the previous when it is ltr — read the direction, do not assume.
   Native <input type="range"> already flips in RTL; do not fight it or double-correct.
4. A motion card's name button exposes aria-expanded reflecting whether the card is
   open, and Enter/Space toggles it. Escape while focus is anywhere inside an open
   card closes that card and returns focus to its name button.
5. Every icon-only button (play, delete, and the change-row drop button) gets an
   aria-label in the panel's UI language. They currently carry glyphs only.
6. Pressing Delete or Backspace while a card's name button has focus deletes that
   interaction, and setStatus reports what was deleted so the action is not silent.
7. refresh() preserves focus: after any re-render the previously focused control is
   focused again, identified by a stable key (interaction id + field name), not by
   DOM index. If that control no longer exists, focus moves to the card's name button,
   and if the card is gone, to the add-motion button.
8. A slider and its paired number input stay in sync when either is changed by
   keyboard, with the same clamping and step the mouse path already applies.
9. No focus-visible outline is suppressed anywhere; if a custom ring is added it must
   be visible against both the panel surface and the active blue fill.
10. Nothing in the generated output changes: the CSS produced by motionCss.ts for a
    given document is byte-identical before and after this task.
</requirements>

<interface>
Keyboard contract for the panel, to be documented in a comment at the top of

  Arrow keys        within the preset strip; within a slider (native)
  Home / End        first / last preset
  Enter / Space     activate the focused button; toggle a card open or closed
  Escape            close the open card, focus returns to its name button
  Delete/Backspace  delete the focused card's interaction

No new global shortcut is registered — everything is scoped to the panel subtree, so
it cannot collide with the canvas shortcuts in designApp.ts.
</interface>
